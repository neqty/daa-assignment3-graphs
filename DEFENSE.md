# Защита: короткие ответы по собственной реализации

## Что показать за 3–5 минут

1. `./mvnw test`: независимые проверки, включая SCC на 100 000 вершинах.
2. `benchmark.Demo data/disconnected.txt`: оба MST возвращают вес 8, три компоненты, петля не включается.
3. `benchmark.Demo data/cyclic.txt`: Kosaraju выделяет три SCC, Kahn сообщает о цикле.
4. `benchmark.Demo data/dag.txt`: несколько источников, отрицательные рёбра, восстановленный путь к 5.
5. `java -jar target/assignment3-graphs-1.0.jar --quick`: контрольные значения и реальные счётчики.
6. Открыть полный CSV, графики и таблицу сложности в REPORT.md.

## Graph

**Почему список смежности?** Хранение O(V+E), перебор соседей O(outdegree(v)). Матрица требует O(V²), даже если рёбер мало.

**Где направленность?** Флаг `directed` в одном классе. Ненаправленное ребро добавляется в оба списка смежности, но в `edges()` хранится один раз. Поэтому Prim сканирует 2m записей, а Kruskal сортирует m логических рёбер.

**Почему суммы — long, а вес — int?** Каждое ребро помещается в int, сумма многих рёбер может выйти за его диапазон. Сравниваем веса через Integer.compare, а не вычитание с риском переполнения.

## DSU

**Что хранит parent?** Лес служебных деревьев представителей множеств; эти ссылки не обязаны быть рёбрами исходного графа.

**find?** Идём до корня, затем вторым циклом перенаправляем весь посещённый путь на корень. Это полное сжатие пути, рекурсия не используется.

**union?** Находим два корня. Если они одинаковы, объединять нечего. Иначе меньшее дерево по числу элементов прикрепляем к большему и уменьшаем components.

**Сложность?** Создание O(V); find/union амортизированно O(α(V)) при обеих эвристиках. Отдельный вызов не обязан быть O(1); без сжатия объединение по размеру ограничивает высоту O(log V).

## MST

**Определение?** Минимальное по сумме весов дерево, покрывающее все вершины связного неориентированного графа. V−1 ребро. Для несвязного графа — лес, V−C рёбер.

**Kruskal?** Сортируем рёбра, берём только соединяющие разные DSU-компоненты. Цикл образуется тогда, когда между концами уже есть путь.

**Prim?** Растим одну компоненту. Очередь хранит рёбра к непосещённым вершинам. Устаревший кандидат пропускаем, если его конечная вершина уже включена. После завершения компоненты ищем следующую непосещённую вершину.

**Почему корректны?** Свойство разреза: лёгкое ребро через разрез, согласованный с уже выбранными рёбрами, безопасно. В существующем MST можно заменить пересекающее тот же разрез более тяжёлое ребро на выбранное, не увеличив вес.

**Почему результаты могут отличаться?** При равных весах MST не обязательно единственно. Сравниваем общий вес и свойства дерева, а не точный список рёбер.

**Отрицательные веса допустимы?** Да, для MST знак веса не мешает свойству разреза. Петля не соединяет компоненты и не входит в дерево.

**Какая именно сложность Prim у нас?** Lazy-очередь может хранить O(E) рёбер, поэтому O(V+E log E), память O(V+E). Нельзя автоматически приписывать нашей реализации оценку варианта с decrease-key.

## Kosaraju

**Что такое SCC?** Максимальная группа вершин, в которой из любой вершины можно дойти до любой другой по направлениям рёбер.

**Два прохода?** Первый DFS записывает вершины при завершении, затем разворачиваем рёбра и обходим вершины в обратном порядке завершения. Каждый новый DFS второго прохода даёт одну SCC.

**Почему не порядок входа?** Для выделения SCC нужен порядок завершения: он отражает зависимости между компонентами. Поэтому первый DFS хранит индекс следующего ребра и добавляет вершину в finish только после обработки потомков.

**Зачем итеративность?** Цепочка из 100 000 вершин может переполнить стек рекурсивных вызовов JVM. Собственный стек — массив в куче, размер O(V).

**Всегда ли SCC означает deadlock?** Циклические зависимости находятся в SCC из нескольких вершин или одиночной SCC с петлёй. Одиночная вершина без петли не образует цикл; прикладной deadlock дополнительно зависит от смысла зависимостей.

## Kahn и DAG

**Что такое топологический порядок?** Для каждого ребра u→v вершина u расположена раньше v. Он существует тогда и только тогда, когда направленный граф ацикличен.

**Как работает Kahn?** Очередь вершин с нулевой входящей степенью. Извлекаем вершину, уменьшаем степени её соседей. Новые нулевые степени добавляем в очередь.

**Как обнаруживается цикл?** Если обработано меньше V вершин, оставшиеся вершины не могут быть удалены таким способом: в остатке есть цикл. Код возвращает hasCycle=true и пустой порядок, а не ошибочный частичный результат.

**Кратчайшие пути?** Проходим вершины в топологическом порядке и релаксируем каждое исходящее ребро один раз. Когда обрабатываем v, все её предшественники уже обработаны: это основа доказательства по индукции.

**Почему несколько источников?** По заданию все вершины с indegree=0 стартуют с расстояния 0. Это эквивалентно виртуальному источнику с нулевыми рёбрами к ним. Это не запуск из произвольно выбранной вершины 0.

**Почему разрешены отрицательные веса?** В DAG нет циклов, значит, отрицательный цикл невозможен. В общем графе отрицательные рёбра допускаются для Bellman–Ford; проблема конечного оптимума возникает при достижимом отрицательном цикле. Dijkstra не подходит для произвольных отрицательных весов.

**Как восстановить путь?** При улучшении расстояния записываем parent[to]=from. От целевой вершины идём назад до -1, затем разворачиваем список.

## Метрики и выбор алгоритма

**Почему не только время?** На время влияют JIT, сборщик мусора, железо и фоновые процессы. Счётчики отражают конкретные операции; медиана пяти запусков снижает влияние отдельных выбросов.

**Почему у Kruskal scans не показывает E log E?** Сортировка считается через comparisons, а edgeScans — только последующий проход. После нахождения MST Kruskal останавливается. Логарифмический множитель нужно искать в сравнениях сортировки.

**Почему 20n называется dense, хотя это O(n)?** Так названа более плотная из двух серий задания. Обе серии имеют E=Θ(V); это не асимптотически плотные графы с E=Θ(V²).

**Что выбирать?** Список рёбер и MST — удобно Kruskal; список соседей и рост MST — Prim. Для действительно плотных простых графов полезен отдельный матричный Prim O(V²). SCC — Kosaraju; порядок зависимостей — Kahn; кратчайшие пути в DAG — топологические релаксации. Ни один из этих методов не является универсально лучшим.

**Доказали ли графики сложность?** Нет: они подтверждают ожидаемый рост на выбранных входах. Асимптотическую оценку обосновываем анализом кода, а корректность — инвариантами и доказательствами; тесты находят ошибки, но не заменяют доказательство.
